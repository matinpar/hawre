یک وب‌اپلیکیشن **رایگان و متن‌باز** برای آشنایی و Match کردن کاربران؛ ساخته‌شده با Next.js 14 (App Router)، TypeScript، Tailwind CSS و Prisma.
رابط کاربری کاملاً **فارسی و راست‌چین (RTL)** و طراحی **Mobile First** است.

> ⚠️ این پروژه یک MVP آزمایشی است: هیچ سیستم پرداخت، اشتراک، تبلیغات یا قابلیت پولی ندارد. نام، لوگو، رنگ‌بندی، آیکون‌ها، متن‌ها و کد آن کاملاً مستقل و اختصاصی است و از هیچ دارایی دارای کپی‌رایت متعلق به برندهای دیگر استفاده نشده است. تصاویر نمونه، آواتارهای SVG تولیدشده توسط خود پروژه هستند.

## ۱. پشته فناوری و تصمیم‌های معماری

| لایه | انتخاب | دلیل |
|---|---|---|
| Frontend | Next.js 14 (App Router) + React 18 + TypeScript | یک پروژه واحد برای UI و API، رندر سمت سرور برای صفحات محافظت‌شده |
| استایل | Tailwind CSS 3 + کامپوننت‌های سفارشی (`nv-btn`, `nv-card`, …) | طراحی سریع، Mobile First، سازگار با RTL |
| Backend | Route Handlers در `src/app/api` (REST) | بدون سرور جداگانه، ساده‌ترین و کم‌هزینه‌ترین گزینه |
| اعتبارسنجی | Zod (سمت سرور + اعتبارسنجی مقدماتی سمت کلاینت) | پیام‌های خطای فارسی، جلوگیری از داده نامعتبر |
| احراز هویت | JWT امضاشده (jose) داخل کوکی **HttpOnly** + bcrypt برای رمز | بدون وابستگی به سرویس پولی، ساده و امن |
| دیتابیس | Prisma ORM + **SQLite** (پیش‌فرض) | کم‌هزینه‌ترین راه اجرا؛ با تغییر یک خط به PostgreSQL می‌رود |
| ذخیره‌سازی تصویر | فایل‌سیستم محلی در `public/uploads` با بررسی امضای فایل | بدون هزینه و بدون سرویس بیرونی |
| انیمیشن | CSS/Tailmind خالص (بدون کتابخانه اضافی) | حجم کمتر، کنترل کامل روی Swipe |

### تصمیم‌های ثبت‌شده (طبق درخواست «ساده‌ترین، امن‌ترین، کم‌هزینه‌ترین»)

- **SQLite به‌جای PostgreSQL در حالت پیش‌فرض:** برای اجرای فوری بدون نصب سرور دیتابیس. schema کاملاً سازگار است؛ برای مهاجرت کافی است در `prisma/schema.prisma` مقدار `provider` را به `postgresql` تغییر دهید و `DATABASE_URL` را به رشته اتصال Postgres ست کنید، سپس `npx prisma migrate dev`.
- **ارسال ایمیل شبیه‌سازی‌شده:** هیچ سرویس ایمیل پولی متصل نشده است. لینک «تأیید ایمیل» و «بازیابی رمز» در کنسول سرور چاپ می‌شود و در حالت غیر-Production در پاسخ API نیز برگردانده می‌شود (`devVerifyUrl` / `devResetUrl`) تا جریان کار کاملاً قابل تست باشد. برای Production کافی است در `src/app/api/auth/register/route.ts` و `forgot-password/route.ts` جای `console.info` را با ارائه‌دهنده ایمیل دلخواه پر کنید.
- **Rate Limit مبتنی بر دیتابیس** (جدول `RateLimit`) به‌جای Redis، برای حذف وابستگی و هزینه.
- **فاصله تقریبی**: هیچ مختصات جغرافیایی ذخیره نمی‌شود. فاصله نمایش‌داده‌شده یک عدد پایدار و شبه‌تصادفی بر پایه شناسه کاربر است تا حریم خصوصی مکانی کاملاً حفظ شود.
- **به‌روزرسانی چت با Polling هر ۸ ثانیه** به‌جای WebSocket/سرویس Realtime پولی.

## ۳. نصب و اجرا

پیش‌نیاز: **Node.js 20 یا بالاتر**.

```bash
# ۱) نصب وابستگی‌ها
npm install

# ۲) ساخت فایل محیطی
cp .env.example .env
#   سپس مقادیر AUTH_SECRET، ADMIN_PASSWORD و SEED_USER_PASSWORD را پر کنید
#   تولید کلید تصادفی:  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

# ۳) ساخت دیتابیس و اعمال Migrationها
npx prisma migrate dev

# ۴) داده‌های آزمایشی
npm run db:seed

# ۵) اجرا در حالت توسعه
npm run dev          # http://localhost:3000

# اجرا در حالت Production
npm run build && npm start
```

## ۴. متغیرهای محیطی

فایل `.env.example`:

```env
DATABASE_URL="file:./dev.db"      # یا postgresql://user:pass@host:5432/hawre
AUTH_SECRET="…"                   # کلید امضای JWT (حداقل ۳۲ کاراکتر تصادفی)
APP_URL="http://localhost:3000"   # آدرس پایه برای لینک‌ها و Callback گوگل
GOOGLE_CLIENT_ID=""               # اختیاری؛ خالی باشد دکمه گوگل پیام راهنما می‌دهد
GOOGLE_CLIENT_SECRET=""
ALLOW_TOKEN_FALLBACK=""         # true/false — نشست جایگزین مبتنی بر توکن (پیش‌فرض: فقط در توسعه)
COOKIE_CROSS_SITE=""            # true/false — تعیین دستی SameSite کوکی نشست
ADMIN_EMAIL="admin@hawre.test"
ADMIN_PASSWORD="…"                # رمز مدیر — هرگز داخل کد قرار نمی‌گیرد
SEED_USER_PASSWORD="…"            # رمز کاربران آزمایشی
```

- فایل `.env` در `.gitignore` قرار دارد و **نباید Commit شود**.
- `GOOGLE_CLIENT_SECRET` فقط در سرور خوانده می‌شود؛ هیچ Secret ای در باندل Frontend نیست (هیچ متغیر `NEXT_PUBLIC_*` حساسی تعریف نشده است).

## ۵. ساختار دیتابیس

| مدل | فیلدهای کلیدی | نکته |
|---|---|---|
| **User** | id, email (unique), passwordHash?, authProvider, googleId (unique), emailVerified, role, accountStatus, createdAt, updatedAt, lastActiveAt | `role` فقط `USER`/`ADMIN`؛ همیشه از DB خوانده می‌شود نه از توکن |
| **Profile** | userId (unique), displayName, birthDate, gender, preferredGender, city, bio, interests (CSV), ageMin, ageMax, maxDistance, profileCompleted | Index روی gender، city، profileCompleted |
| **ProfilePhoto** | userId, imageUrl, isPrimary, sortOrder | Index ترکیبی `(userId, sortOrder)` |
| **UserAction** | fromUserId, toUserId, actionType (`LIKE`/`PASS`) | **Unique روی (fromUserId, toUserId)** → جلوگیری از رکورد تکراری |
| **Match** | userOneId, userTwoId, status, createdAt, lastMessageAt | **Unique روی (userOneId, userTwoId)** و ترتیب همیشه لغوی → Match دوطرفه تکراری غیرممکن |
| **Message** | matchId, senderId, receiverId, content, isRead, createdAt, deletedAt | حذف نرم؛ Index روی `(matchId, createdAt)` و `(receiverId, isRead)` |
| **Block** | blockerId, blockedId | Unique ترکیبی |
| **Report** | reporterId, reportedUserId, reason, description, status | Index روی `(status, createdAt)` |
| **Notification** | userId, type, title, body, isRead | Index روی `(userId, isRead)` |
| **Settings** | userId (unique), showDistance, notifyMatches, notifyMessages, discoverable | تنظیمات حریم خصوصی |
| **Token** | userId, tokenHash (unique), type, expiresAt, usedAt | توکن تأیید ایمیل/بازیابی رمز، **هش‌شده** ذخیره می‌شود |
| **RateLimit** | key (unique), count, windowEnd | محدودیت نرخ درخواست بدون Redis |

> در SQLite از `enum` پشتیبانی نمی‌شود؛ مقادیر ثابت به‌صورت `String` ذخیره و در `src/lib/constants.ts` تایپ می‌شوند. هنگام مهاجرت به PostgreSQL می‌توانید آن‌ها را به enum واقعی تبدیل کنید.

## ۶. Migration و داده‌های آزمایشی

```bash
npx prisma migrate dev      # اعمال مهاجرت‌ها (پوشه prisma/migrations)
npm run db:seed             # ۱۲ پروفایل + ۱ مدیر + انتخاب‌ها + ۲ Match + ۵ پیام + ۱ گزارش
npm run db:reset            # ریست کامل و Seed مجدد
```

داده‌های نمونه شامل: ۱۲ پروفایل با نام‌های **ساختگی**، شهرهای مختلف (تهران، اصفهان، شیراز، مشهد، تبریز، کرج، رشت، یزد، اهواز)، علایق متفاوت، آواتارهای SVG تولیدشده در `public/seed/`، ۸ انتخاب نمونه، ۲ Match دوطرفه، ۵ پیام و ۱ گزارش برای آزمایش پنل مدیریت.
ورود کاربران آزمایشی: ایمیل‌های `…@hawre.test` با رمز موجود در `SEED_USER_PASSWORD` (مثلاً `armita@hawre.test`).

## ۸. فعال‌سازی Google OAuth

1. وارد [Google Cloud Console](https://console.cloud.google.com/) شوید و یک پروژه بسازید.
2. از بخش **APIs & Services → OAuth consent screen** نوع External را انتخاب و اطلاعات پایه را پر کنید (scopeهای `openid`, `email`, `profile`).
3. از **Credentials → Create Credentials → OAuth client ID**، نوع *Web application* را بسازید.
4. در **Authorized redirect URIs** این آدرس را اضافه کنید:
   ```
   http://localhost:3000/api/auth/google/callback
   ```
   (در Production همان دامنه واقعی + همین مسیر)
5. `GOOGLE_CLIENT_ID` و `GOOGLE_CLIENT_SECRET` را در فایل `.env` بگذارید و سرور را دوباره اجرا کنید.

رفتار پیاده‌سازی‌شده:

- جریان استاندارد **Authorization Code** با پارامتر `state` امضاشده در کوکی HttpOnly (محافظت CSRF).
- رمز عبور Google هرگز از کاربر خواسته نمی‌شود.
- نام، ایمیل و تصویر پروفایل (در صورت اجازه) دریافت می‌شود؛ تصویر به‌عنوان عکس اصلی اولیه ثبت می‌گردد.
- اگر ایمیل قبلاً با روش ایمیل/رمز ثبت شده باشد، حساب Google به همان کاربر **متصل** می‌شود و `authProvider` به `BOTH` تغییر می‌کند (ورود با هر دو روش ممکن می‌ماند).
- اگر متغیرها تنظیم نشده باشند، دکمه گوگل کاربر را با یک پیام فارسی راهنما به صفحه ورود برمی‌گرداند (بدون خطای ۵۰۰) — یعنی پروژه بدون کلید هم کاملاً قابل اجرا و تست است.

## ۱۰. امنیت و حریم خصوصی

- **رمز عبور** با `bcrypt` (cost 12) هش می‌شود؛ هرگز خام ذخیره یا به Frontend ارسال نمی‌شود.
- **نشست (دوحالته)**: JWT امضاشده با HS256. حالت اصلی، کوکی `HttpOnly` است (روی `localhost` با `SameSite=Lax` و روی سایر میزبان‌ها با `SameSite=None; Secure; Partitioned`). اما برخی مرورگرها کوکی شخص‌ثالث را داخل iframe کاملاً مسدود می‌کنند؛ برای همین در این حالت سرور همان توکن را در بدنه پاسخ ورود برمی‌گرداند و کلاینت آن را نگه داشته و در هدر `Authorization: Bearer` می‌فرستد. این جایگزین با `ALLOW_TOKEN_FALLBACK` کنترل می‌شود (پیش‌فرض: فعال در توسعه، غیرفعال در Production، چون نگهداری توکن در مرورگر در برابر XSS ضعیف‌تر از کوکی HttpOnly است). گزینه «مرا به خاطر بسپار» عمر نشست را از ۱ روز به ۳۰ روز می‌برد.
- **اعتبارسنجی کامل سمت سرور** با Zod روی همه Endpointها (اعتبارسنجی کلاینت فقط برای تجربه کاربری است).
- **SQL Injection**: تمام کوئری‌ها از Prisma (پارامتری) عبور می‌کنند؛ هیچ SQL خامی وجود ندارد.
- **XSS**: React به‌صورت پیش‌فرض escape می‌کند و علاوه بر آن، bio و پیام‌ها با `sanitizeText` از تگ‌های HTML، `javascript:` و هندلرهای `on*` پاک می‌شوند. هیچ‌جا از `dangerouslySetInnerHTML` استفاده نشده است.
- **Rate limiting**: ثبت‌نام (۵/۱۵دقیقه در هر IP)، ورود (۱۰/۱۰دقیقه در هر IP و ۵/۱۰دقیقه در هر ایمیل)، فراموشی رمز (۵/۱۵دقیقه)، تغییر رمز (۵/۱۵دقیقه)، ارسال پیام (۶۰/دقیقه)، انتخاب‌ها (۳۰۰/ساعت)، آپلود عکس (۲۰/ساعت)، گزارش (۱۰/ساعت).
- **محافظت صفحات**: چون نشست می‌تواند بدون کوکی برقرار باشد، صفحات محافظت‌شده سمت کلاینت (`AppFrame`) کنترل می‌شوند و کاربر بدون نشست به `/login` هدایت می‌شود؛ اما **هیچ داده‌ای بدون احراز هویت سمت سرور برگردانده نمی‌شود** — کنترل واقعی روی تک‌تک APIها اعمال می‌گردد (صفحه بدون داده خالی می‌ماند).
- **کنترل دسترسی**: هر کاربر فقط پروفایل، عکس‌ها، تنظیمات و پیام‌های خودش را می‌تواند تغییر دهد؛ عضویت در Match قبل از هر عملیات چت بررسی می‌شود.
- **نقش مدیر** در سمت سرور (`requireAdmin`) و از روی رکورد پایگاه داده بررسی می‌شود؛ صفحه `/admin` هم در Server Component و هم در Middleware محافظت شده است — پنهان کردن دکمه به‌تنهایی کافی نیست.
- **آپلود فایل**: فقط `image/jpeg`, `image/png`, `image/webp`، حداکثر ۳MB، حداکثر ۶ عکس، و علاوه بر content-type، **امضای باینری فایل (magic bytes)** بررسی می‌شود تا فایل جعلی/اسکریپتی آپلود نشود. نام فایل تصادفی تولید می‌گردد (بدون Path Traversal).
- **افشای اطلاعات**: تابع `toPublicProfile` دقیقاً مشخص می‌کند چه چیزی عمومی است. `email`، `passwordHash`، `googleId`، `role` و تنظیمات هرگز در پاسخ عمومی نیستند. پیام خطای ورود برای «کاربر ناموجود» و «رمز اشتباه» یکسان است.
- **حریم خصوصی مکانی**: فقط شهر و یک فاصله تقریبی؛ هیچ مختصاتی ذخیره نمی‌شود و کاربر می‌تواند نمایش فاصله را خاموش کند.
- **سن قانونی**: تاریخ تولد در سرور بررسی می‌شود؛ کمتر از ۱۸ سال پذیرفته نمی‌شود.
- **حذف حساب**: با تأیید صریح عبارت «حذف حساب». سیاست: پروفایل، عکس‌ها (از دیسک هم پاک می‌شوند)، توکن‌ها، اعلان‌ها و انتخاب‌ها **حذف** و ایمیل با مقدار ناشناس جایگزین می‌شود؛ Matchها غیرفعال می‌شوند تا گفت‌وگوی طرف مقابل خراب نشود (ناشناس‌سازی به‌جای حذف آبشاری).
- **هدرهای امنیتی**: `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` در `next.config.mjs`.

## ۱۳. استقرار روی سرور (Docker)

نسخه Production به‌صورت کامل آماده است. راهنمای گام‌به‌گام: **[`docs/DEPLOY.md`](docs/DEPLOY.md)**

```bash
cp .env.production.example .env.production   # AUTH_SECRET و ADMIN_PASSWORD را پر کنید
docker compose up -d --build                 # برنامه روی پورت ۳۰۰۰
docker compose --profile proxy up -d         # به‌همراه Nginx روی ۸۰/۴۴۳
```

| فایل | نقش |
|---|---|
| `Dockerfile` | ایمیج چندمرحله‌ای بر پایه `node:20-slim` با خروجی `standalone` نکست، کاربر غیر‌root، `tini` و `HEALTHCHECK` |
| `docker-compose.yml` | سرویس برنامه + والیوم‌های پایدار `hawre-data` (دیتابیس) و `hawre-uploads` (عکس‌ها)، و سرویس اختیاری `nginx` با پروفایل `proxy` |
| `docker/entrypoint.sh` | اعتبارسنجی `AUTH_SECRET`/`DATABASE_URL`، اجرای `prisma migrate deploy`، ساخت حساب مدیر، سپس اجرای سرور |
| `docker/nginx.conf` | پروکسی معکوس با HTTPS، HSTS، کش فایل‌های ساکن و سقف آپلود ۶ مگابایت |
| `prisma/create-admin.js` | نسخه JS خالص ساخت حساب مدیر (بدون نیاز به وابستگی‌های توسعه) |
| `.env.production.example` | همه متغیرهای لازم برای Production همراه با توضیح |
| `GET /api/health` | بررسی سلامت برنامه و اتصال دیتابیس (برای HEALTHCHECK و Load Balancer) |

**نکات امنیتی Production** (به‌صورت پیش‌فرض اعمال شده‌اند):
- `ALLOW_TOKEN_FALLBACK=false` → فقط کوکی HttpOnly، بدون توکن Bearer.
- `ALLOWED_FRAME_ANCESTORS='self'` → نمایش در iframe دیگران ممنوع.
- کانتینر با کاربر `hawre` (UID 1001) و بدون دسترسی root اجرا می‌شود.
- اگر `AUTH_SECRET` کوتاه‌تر از ۳۲ کاراکتر باشد، کانتینر با پیام روشن بالا نمی‌آید.

- 📱 روی موبایل همه‌چیز وسط‌چین و روی دسکتاپ راست‌چین است

**بازطراحی کاوش:**

- ❤️ **دکمه قلب سمت راست و ضربدر سمت چپ** — هم‌جهت با منطق کشیدن؛ روی موبایل دکمه‌ها شناور روی پایین عکس و بالای نوار ناوبری قرار دارند
- 👉 **کشیدن به راست = پسندیدن، کشیدن به چپ = رد کردن** با مهرهای زندهٔ «پسندیدم / رد شد»، هالهٔ رنگی هم‌جهت، چرخش و پرتاب کارت
- 🃏 **پیش‌نمایش کارت بعدی** پشت کارت فعلی (حس «دسته کارت» واقعی)
- 📖 دکمهٔ **بیشتر/بستن** برای معرفی کامل و همهٔ علاقه‌مندی‌ها بدون خروج از کاوش
- 🎨 **۱۰ تصویر تصویرسازی‌شدهٔ اختصاصی** (۶ دخترانه، ۴ پسرانه) برای پروفایل‌های آزمایشی در `public/seed/` — هیچ‌کدام عکس واقعی از افراد نیستند
- راهنمای جهت کشیدن بالای کارت، و پشتیبانی از کلیدهای ← و → در دسکتاپ

**بازطراحی حرفه‌ای چت:**

- 🗓 **جداکننده تاریخ چسبان** (امروز / دیروز / تاریخ کامل با تقویم هر زبان)
- 💬 **گروه‌بندی پیام‌ها**: پیام‌های پشت‌سرهم یک نفر تا ۵ دقیقه در یک گروه، با آواتار کوچک فقط کنار آخرین پیام
- ✔️ **رسید خواندن گرافیکی**: یک تیک = ارسال شد، دو تیک = خوانده شد
- ⌨️ **کادر نوشتن هوشمند**: ارتفاع خودکار، **Enter** برای ارسال و **Shift+Enter** برای خط جدید، شمارنده کاراکتر در ۱۰۰ کاراکتر پایانی
- ⬇️ **دکمه شناور «پیام جدید»** وقتی کاربر بالای گفت‌وگوست (اسکرول خودکار فقط وقتی پایین صفحه است)
- ⋮ **منوی اقدامات** (پروفایل، گزارش، مسدود کردن، حذف گفت‌وگو) به‌جای چند دکمهٔ پراکنده در هدر
- 🟢 نقطهٔ آنلاین با **پالس زنده** و حالت خالی با **سه پیشنهاد شروع گفت‌وگو** که با یک کلیک در کادر نوشتن می‌نشینند
- همه‌چیز سازگار با حالت تاریک، RTL/LTR و هر چهار زبان

**چندزبانه‌سازی:**

- 🌍 چهار زبان: **فارسی، کردی سۆرانی، عربی و انگلیسی** با سوییچ در تنظیمات و در هدر/پاورقی صفحه نخست.
- جهت صفحه خودکار عوض می‌شود (`dir="rtl"` برای فارسی/کردی/عربی و `dir="ltr"` برای انگلیسی) و `lang` هم به‌روزرسانی می‌گردد.
- الگوی ترجمه: **کلید = همان متن فارسی** (`src/lib/i18n-dict.ts`). هر رشته‌ای که ترجمه نداشته باشد به فارسی نمایش داده می‌شود، پس هیچ صفحه‌ای هرگز خالی نمی‌ماند. افزودن زبان تازه = افزودن یک شیء به همان فایل.
- انتخاب زبان در `localStorage` + کوکی ذخیره می‌شود و بدون وابستگی به هیچ کتابخانه‌ای پیاده شده است (~۹۷ رشته در هر زبان).

**اعتماد و ارتباط (تازه‌ترین):**

- 📧 **ارسال واقعی ایمیل** با Resend (`src/lib/mailer.ts`) و چهار قالب HTML فارسی و RTL: تأیید ایمیل، بازیابی رمز، «آشنایی دوطرفه تازه» و نتیجه تأیید هویت. بدون کلید API، رفتار قبلی (چاپ در کنسول) حفظ می‌شود.
- ✔️ **نشان «پروفایل تأییدشده»**: کاربر سلفیِ **ژست‌دار** می‌فرستد (ژست پایدار و اختصاصی هر کاربر)، مدیر در صف `/admin` بررسی می‌کند، و **تصویر بلافاصله پس از بررسی برای همیشه حذف می‌شود**. نشان در کاوش، آشنایی‌ها، جزئیات پروفایل و چت دیده می‌شود.

**زیرساخت و کیفیت:**

- **نشان پیام خوانده‌نشده** روی «آشنایی‌ها» در هدر و نوار پایین (`GET /api/notifications/unread`، به‌روزرسانی هر ۲۰ ثانیه)
- **PWA کامل** (`src/app/manifest.ts`) — قابل نصب روی موبایل، اجرای مستقل، آیکون و میان‌بُرها
- **صفحه خطای اختصاصی** (`src/app/error.tsx`) با کد پیگیری و دکمه تلاش دوباره
- **اسکلت بارگذاری سراسری** (`src/app/loading.tsx`)
- **`robots.ts` و `sitemap.ts`** — کنترل دقیق ایندکس؛ صفحات خصوصی هرگز ایندکس نمی‌شوند
- **CI در GitHub Actions** (`.github/workflows/ci.yml`): typecheck، lint، migrate، build و ساخت ایمیج داکر

## ۱۵. قابلیت‌های آینده

- ارسال واقعی ایمیل (تأیید و بازیابی) با یک ارائه‌دهنده SMTP/API
- Realtime واقعی برای چت (WebSocket / Server-Sent Events) به‌جای Polling
- ذخیره‌سازی ابری تصاویر (S3 سازگار) + پردازش و فشرده‌سازی تصویر و حذف EXIF
- احراز هویت دومرحله‌ای و مدیریت نشست‌های فعال
- تعدیل خودکار محتوا (تشخیص تصویر/متن نامناسب) و صف بررسی مدیریتی پیشرفته
- الگوریتم پیشنهاد هوشمندتر (وزن‌دهی رفتار، بازخورد ضمنی)
- اعلان Push و مرکز اعلان درون‌برنامه‌ای (مدل `Notification` از قبل آماده است)
- تأیید هویت پروفایل (Verified Badge)
- چندزبانه کردن (i18n) و افزودن حالت تیره
- تست‌های خودکار واحد/یکپارچه (Vitest + Playwright) و CI
- مهاجرت به PostgreSQL + enum واقعی و ایندکس‌های جستجوی متنی
